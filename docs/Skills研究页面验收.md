## 数据与画面核对

独立从 API 样本计算数量、去重作者与分组，对照 report 与页面四张统计卡；核对全部 5 个选题的证据 ID 指向有效样本、翻页后可访问全部选题。抽查第一篇详情的正文、点赞/收藏/评论数、来源链接，均与后端记录一致。未知互动量按“未知”呈现，不伪装成 0。

1366×768 下，研究列表、研究概览、标题观察、候选选题、样本明细、写作页均无整页纵向或横向溢出；长文与长选题列表在独立区域阅读。长观察和选题角度提供完整详情入口，没有丢失原文。浏览器未捕获 JavaScript 异常。

这些检查证明页面忠实呈现后端数据，不能替代对小红书原始内容或模型建议的事实核查。

## 真实运行中发现并修复的问题

1. 首次 MCP 返回未登录，任务如实失败；登录恢复后重试同一研究，未重复建研究。
2. 采样成功后的第一次模型响应不能解析为 JSON，研究保留样本并标记部分完成。为百炼域名上的 Qwen3.5/3.6/3.7 Flash/Plus/Max 增加显式非思考 JSON Object 模式，其它兼容服务不发送这些专用参数。通过真实后续分析验证成功；首次失败的完整响应未保留，未武断归因为某一种具体截断原因。
3. 非法 JSON 原来丢失提供商 token 用量；现在即使解析失败也保留响应已报告的输入/输出 token，避免把模型失败当成零消耗。
4. 分析任务成功后研究仍保留旧 partial/error；现在仅在采集已结束（progress >=80）的失败分析恢复时同步 completed。采集本身不完整时仍保持 partial，历史失败 job 保留。当前研究已根据实际成功任务修复状态，没有额外模型调用。
5. 真实长分类、长选题及失败状态造成页面溢出；压缩短屏统计卡、合并状态与操作栏、研究与选题分页，长角度通过详情查看。缺失日期显示“发布时间未知”，标题规则明确说明实际匹配范围。
6. 后台任务入口原来继续列出同一研究已被成功重试取代的失败；现在显示每项研究最新的采集/分析任务，任务条目带研究名称，避免把历史错误当成当前状态。

参考：[百炼结构化输出](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output)、[思考模式](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)。
