# 代码阅读指南

项目由 React 页面、FastAPI 接口、SQLite 数据库和独立 worker 组成。前后端源码已补充中文注释，主要解释模块职责、数据流和关键约束。

## 建议阅读顺序

1. [前端类型](../frontend/src/types.ts)和[后端数据契约](../backend/src/xhs_content_agent/schemas.py)：先认识研究、样本、选题、草稿与任务。
2. [前端入口](../frontend/src/main.tsx)：理解共享数据快照、路由、研究选择和轮询。
3. [请求层](../frontend/src/api.ts)：理解页面如何读数据、提交任务和等待生成结果。
4. [HTTP 接口](../backend/src/xhs_content_agent/app.py)：理解请求校验、任务入队、版本冲突与错误响应。
5. [后台执行器](../backend/src/xhs_content_agent/worker.py)：按 collection、analysis、draft 阅读三种任务。
6. [数据库操作](../backend/src/xhs_content_agent/storage.py)：理解事务、幂等提交、样本去重及状态同步。

## 一次研究如何执行

研究页提交范围后，`api.ts` 给请求附上幂等键。`app.py` 在同一事务内创建研究和排队任务，立即返回 ID。`worker.py` 领取任务，依次检查 MCP 登录、搜索笔记、读取详情、去重并保存样本，再调用模型分类和生成选题。前端轮询接口刷新进度与结果。

采集数据先保存，分析失败时已有样本仍可使用。重新生成选题会对已有有效样本分析；它不重新采集。取消采用步骤边界检查，点击按钮后正在执行的外部请求可能仍需等待返回。

## 外部调用与数据口径

- [connectors.py](../backend/src/xhs_content_agent/connectors.py)：只读 MCP 白名单，平台字段转换，指标精度和评论覆盖信息。未知互动数保持为空，不能当成零。
- [intelligence.py](../backend/src/xhs_content_agent/intelligence.py)：通过 AgentScope 调用模型，解析 JSON，返回供应商用量；编排由 worker 控制。
- [model_settings.py](../backend/src/xhs_content_agent/model_settings.py)：热读取整组模型配置，安全保存密钥，只向页面返回密钥存在标记。普通任务偏好在入队时快照，模型配置在实际调用时读取。
- [analytics.py](../backend/src/xhs_content_agent/analytics.py)：统计来自未排除样本，模型观察附带证据。样本总数不一定等于模型覆盖数，预算可能限制分析输入。
- [api.mock.ts](../frontend/src/api.mock.ts)：仅用于显式开启的演示模式；真实服务失败不会自动切换到假数据。

## 容易忽略的约束

- 研究和任务是不同对象；一次研究可以有采集、重分析和多个草稿任务。
- 模型输出通过字段校验后，还必须验证证据归属和分类覆盖，才能保存。
- 排除样本不删除数据，但会把已有分析标记为过期。
- 草稿保存必须携带 `base_version`，避免旧页面覆盖新版本；历史版本与最新正文在同一事务保存。
- token 预算预留是保守估算，实际用量以供应商报告为准；未报告的数量不能视为零。
- CSS 后段有意覆盖基础规则。阅读布局时需要同时检查对应宽度、高度的媒体查询。

## 本地检查

在项目根目录执行：

```bash
backend/.venv/bin/ruff check backend/src backend/tests
backend/.venv/bin/pytest -q backend/tests
npm run build --prefix frontend
```

以上用于静态检查、现有后端测试和前端类型检查/构建。源码注释本身不需要触发真实研究或模型调用。
